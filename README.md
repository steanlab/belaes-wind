# belaes-wind

Интерактивная учебная карта: куда могло бы пойти облако выброса БелАЭС по прогнозу ветра. Задумана для случая, когда известно только то, что авария произошла.

Страница: https://steanlab.github.io/belaes-wind/

**Это учебная иллюстрация, а не прогноз и не инструмент оценки риска.**

## Возможности

- Ветер берется из почасового прогноза и меняется со временем. Облако идет по ветру там и тогда, где оно находится.
- Выбор момента аварии: сейчас или до 24 часов назад. Для прошедшей аварии симуляция сразу показывает, где облако уже может быть.
- Блок «Где я?»: место из браузера (определяется только в браузере и никуда не отправляется) или город из списка. Короткий итог: дойдет ли облако, через сколько и когда, и ссылка на этот итог.
- Простая оценка устойчивости атмосферы (класс Паскуилла по скорости ветра, высоте солнца и облачности) задает ширину облака и дает пояснение о рассеивании.
- Часы с момента аварии, пауза и скорость ×0,5, ×1, ×2, ×4. Карта сама отдаляется, когда облако подходит к краю экрана.
- Режим «А если ветер другой?»: свое направление и скорость ветра.
- Сводка «Накрыто городов», список из 29 городов (сначала накрытые, по времени прибытия), клик по городу центрирует карту на нем.
- Пять языков: русский, белорусский, английский, польский, литовский. Язык берется из `?lang=`, потом из сохраненного выбора, потом из языка браузера.
- «Поделиться» и «Сохранить картинку» (PNG 1200×630 с итогом симуляции).
- Ссылки на официальные источники измерений (EURDEP, польский PAA, литовский RSC, Белгидромет, БелАЭС). Значения измерений на странице не показываются.
- Установка как приложение (PWA). Без сети открывается оболочка, но карта и ветер без сети недоступны.

## Параметры ссылки

| Параметр | Значение |
|---|---|
| `lang` | `ru`, `be`, `en`, `pl` или `lt` |
| `wd` | откуда дует ветер, градусы от 0 до 360 (вместе с `ws`) |
| `ws` | скорость ветра, м/с, от 0,5 до 25 (вместе с `wd`) |
| `at` | момент аварии в UTC, формат `2026-11-24T15:00Z`. Принимается не из будущего и не старше 24 часов |
| `city` | идентификатор города из списка для блока «Где я?» (например `minsk`). Координаты из геолокации в ссылку не попадают |
| `run` | `1`: сразу запустить симуляцию |

Примеры: `?lang=be&wd=270&ws=6&run=1`, `?at=2026-11-24T15:00Z&city=minsk&run=1`

## Откуда данные и как они попадают на страницу

Источник: [Open-Meteo](https://open-meteo.com/) (`wind_speed_10m`, `wind_direction_10m`, `cloud_cover`, почасовой прогноз плюс последние 24 часа). Это модельные значения на высоте 10 м, а не измерения. Условия Open-Meteo: бесплатный тариф для некоммерческого использования, лицензия данных CC BY 4.0, ссылка на источник есть на странице.

Сетка 3° (широта 44–68, долгота 6–54, 153 точки). Порядок загрузки:

1. Файл `wind-grid.json` из ветки `data` этого репозитория (`https://raw.githubusercontent.com/steanlab/belaes-wind/data/wind-grid.json`). Его раз в час обновляет GitHub Actions (`.github/workflows/update-wind.yml`, `tools/fetch-wind.js`). Файл старше 3 часов не принимается.
2. Если файла нет или он старый, страница сама запрашивает Open-Meteo тем же набором точек.
3. Если и это не удалось, берется ветер на площадке АЭС на сейчас (одна точка), выбор времени аварии отключается и показывается пояснение.

Так сайт работает и без workflow, просто чаще обращается к Open-Meteo из браузеров посетителей.

Направление ветра в Open-Meteo метеорологическое, то есть **откуда** дует ветер. Облако движется в противоположную сторону: азимут переноса равен направлению ветра плюс 180°.

## Модель

1. Траектория считается шагом 300 с (метод Хойна). На каждом шаге ветер берется из поля: билинейно по пространству и линейно по времени. За краем сетки значения берутся с границы.
2. Ширина облака растет с расстоянием. Половина угла раскрытия зависит от класса устойчивости (`HALF_ANGLE_BY_CLASS`: от 25° для A до 5° для E и F). Класс определяется по скорости ветра, высоте солнца (формулы NOAA) и облачности, при двойном классе берется более устойчивый. Значения углов ориентировочные, из таблицы σθ для классов Паскуилла.
3. «Коридор неопределенности» добавляет ±15° к оси (`AXIS_UNCERTAINTY_DEG`). Это условная величина.
4. Покрытие считается по трапециям между точками пути. Город накрыт, когда он попадает внутрь центральной полосы. Время прибытия берется по пути, а не по прямой.
5. Для прошедшей аварии часы стартуют с числа часов, прошедших с аварии, а города, уже накрытые к этому моменту, отмечаются сразу.
6. Через 48 модельных часов симуляция останавливается.
7. Прозрачность облака уменьшается со временем. Это условный прием, он не передает реальное падение концентрации (оно на порядки).

## Чего в модели нет

Изменения ветра с высотой, высоты и величины выброса, осаждения, дождя, рельефа, концентраций и доз. Ансамбля прогнозов, поэтому вероятностей нет. Ошибок прогноза ветра, которые к концу первых суток заметно растут. Сетка 3° грубая и не видит местных особенностей.

## Что еще важно

- Выбор городов в списке `CITIES` не имеет формального критерия, это иллюстративный набор. Названия городов на пяти языках, литовские названия нужно проверить носителю языка.
- Рекомендации по йоду на странице даны справочно. Доза и показания зависят от возраста и здоровья, решение о профилактике принимают по сообщению властей.
- Страница не собирает данные о посетителях, но браузер обращается к GitHub (файл данных), Open-Meteo, OpenStreetMap и unpkg, и эти сервисы видят IP-адрес.
- Данные EURDEP принадлежат национальным службам и не проверены, поэтому на странице только ссылки.

## Структура

| Файл | Назначение |
|---|---|
| `index.html` | страница, мета-теги, структурированные данные |
| `model.js` | модель без DOM: траектория, устойчивость, покрытие, загрузка сетки |
| `script.js` | карта, интерфейс, «Где я?», загрузка данных |
| `i18n.js` | тексты на пяти языках |
| `style.css` | оформление |
| `manifest.webmanifest`, `sw.js` | установка как приложение и работа без сети |
| `tools/fetch-wind.js` | сбор сетки ветра с Open-Meteo в `wind-grid.json` |
| `.github/workflows/update-wind.yml` | почасовой запуск сбора и публикация в ветку `data` |
| `icons/` | значки приложения (`icon.svg`, PNG разных размеров) |
| `wind-rose-base.svg`, `wind-rose-pointer.svg` | роза ветров |
| `preview-image.jpg` | картинка для соцсетей |

`model.js` и функции геометрии и форматирования в `script.js` не зависят от DOM и Leaflet и экспортируются через `module.exports`, чтобы их можно было проверять в Node.

## Для разработчика

- Новая версия: поменяйте `APP_VERSION` в `script.js` и `VERSION` в `sw.js`, чтобы устаревший кэш приложения был очищен.
- Добавить язык: добавьте блок в `STRINGS` и запись в `LANGS` (`i18n.js`), названия городов в `CITIES` (`script.js`) и пункт в `<select id="langSelect">` (`index.html`).
- Workflow обновления ветра: Actions → Update wind grid → Run workflow (первый запуск создает ветку `data`). Если запуск падает на записи, проверьте Settings → Actions → General → Workflow permissions: нужно Read and write. GitHub может отключить расписание после 60 дней без активности в репозитории, тогда страница автоматически переходит на прямые запросы к Open-Meteo, а workflow включается заново кнопкой в Actions.
- Ветка `data` содержит один коммит, который каждый час перезаписывается принудительно, история не растет. Источник GitHub Pages остается прежним (ветка `main`, корень).
